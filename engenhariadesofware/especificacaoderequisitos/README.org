* Sobre esta pasta
Esta pasta reúne os artefatos de Engenharia de Requisitos (ER) do projeto,
organizados segundo o processo descrito por Ian Sommerville em
/Engenharia de Software/ (cap. 4 — Engenharia de Requisitos).

Sommerville descreve a ER como um processo iterativo (modelo em espiral)
com três atividades principais, sustentadas pelo gerenciamento de requisitos:

1. *Elicitação e análise* — descobrir os requisitos junto aos /stakeholders/.
2. *Especificação* — registrar requisitos de usuário e de sistema.
3. *Validação* — verificar se os requisitos definem o sistema que o cliente quer.
4. *Gerenciamento* — controlar mudanças e rastreabilidade ao longo do tempo.

* Como trabalhar com estes arquivos
- Cada requisito é um /heading/ Org com um bloco =:PROPERTIES:= (ID, tipo,
  prioridade, fonte, status). Isso permite filtrar com =org-sparse-tree= ou
  =org-agenda= e exportar tabelas com =org-columns=.
- Requisitos ainda não confirmados por um stakeholder levam a tag
  =:HIPOTESE:=. Eles *não* devem ser implementados antes da validação.
- Exportação: =C-c C-e h o= (HTML) ou =C-c C-e l p= (PDF via LaTeX).
